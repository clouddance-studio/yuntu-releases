# Support and useful bug reports

A verified public support channel has not yet been announced. The company website domain is still under review. This preparation does not claim that a support email inbox or online feedback endpoint is working.

If your beta distribution supplied a support channel, use that channel. Otherwise retain the report locally until a verified destination is provided. An offline feedback file is not an online submission.

## What to include

- Editor version, channel, and package source.
- Windows version, architecture, and relevant graphics or runtime information.
- The smallest steps that reproduce the problem.
- Expected result, actual result, and the exact error text.
- Whether the issue affects editing, saving, preview, export, installation, or the AI connection.
- A minimal sample project or screenshot that you are allowed to share.

Before attaching anything, remove credentials, discovery files, tokens, private project assets, email addresses, and unrelated user data. Do not attach a full profile or recovery directory by default.

For MCP failures, record the bridge bundle identity, Python version, client version, and whether the editor was restarted or switched to another document. Never include the contents of the private API discovery JSON. A public session ID is not the connection token, but a minimal report usually does not need either.

For a save conflict, preserve both versions and the editor's recovery state before retrying. For an installation issue, keep the exact installer and its release checksum record, and include a sanitized installer error rather than changing Windows security settings.
