## 当前结论

本地仓库已完成英文 README、用户指南、用户 Skill、MCP 接入及发布准备资料；真实截图、示例、最终版本记录和对外上线仍待确认。定位为 **Yuntu Editor 的公开介绍与使用资料入口**：Microsoft Store 承担 Windows 主下载安装和更新，GitHub 承载介绍、文档、示例、规范及后续明确启用的备用材料。无需把编辑器和账号后台源码搬过来。

用户已明确：**以英文为主，主要发布英语地区。** 对外统一使用 Yuntu Editor，README、公开文档导航、指南、FAQ、版本说明、示例及教程均优先英文；截图与演示优先使用英文界面、英文字幕。中文内容按需补充，不要求首发同步双语。本文作为内部准备说明保留中文。

主入口围绕海外版的实际获取和使用流程组织，国内版按需单列说明，不在英文首页并列两套区域政策。英语优先不代表自动开放所有海外市场；具体可用地区以实际服务支持和商店配置为准。

本机编辑器发行真源 `rust-ui-editor/packaging/release.json` 当前为 `1.0.0-beta.3`，通道 `beta`，Windows 文件版本 `1.0.0.3`。这是核对时的开发身份，不能直接标为最新公开版本。

## 首批应该写什么

| 内容 | 应写的信息 | 发布条件 |
| --- | --- | --- |
| 英文 `README.md` | 产品用途、适用用户、真实截图或演示、可用平台、下载状态、上手入口、文档、反馈和许可说明 | 无公开包时明确处于准备阶段，不放假下载按钮 |
| 快速上手 | 安装、首次启动、新建／打开项目、编辑和自动保存、预览、导出一个最小案例 | 按对应公开版本实测，使用用户界面操作说明 |
| 系统与安装说明 | 实际支持的 Windows 版本、x64 架构、必要运行环境、安装／更新／卸载及用户数据位置 | 最低系统和硬件要求须验证，不凭开发机推断 |
| AI / MCP 使用指南 | 外部 AI 工具如何连接、前置安装或配置、最小请求、查看修改及撤销、常见连接问题 | 明确客户端、模型和服务是否需用户另行配置或付费 |
| FAQ 与已知限制 | 账号及联网要求、本地文件、AI 配置、导出范围、版本兼容、数据恢复与常见故障 | 只说明该版本的真实行为 |
| 版本说明模板 | 新增／修复、已知问题、系统要求、兼容性、升级注意事项、下载入口 | 真实发行时再创建对应版本记录 |
| 支持与反馈说明 | 实际可用的反馈渠道、应提供的版本及复现步骤、脱敏方法 | 接收渠道已验证可用；不把未接通的内置反馈写成已提交 |
| 使用条款与隐私入口 | 编辑器使用许可、账号服务与 AI 数据处理说明、支持主体 | 根据最终实际服务及条款填写，不擅自制定授权 |

以上公开资料默认使用英文。可选的 `README.zh-CN.md` 或其他翻译在英文主路径完成后按需增加；如涉及国内版，单独解释其发行与服务范围，不把语言选择等同于服务区域切换。

README 建议按下面的用户阅读顺序组织：

1. **Yuntu Editor**：一句话说明产品用途和面向谁。
2. **Watch the workflow**：一个真实案例的视频或截图。
3. **Availability / Download**：已发布状态、对应商店入口、版本和平台。
4. **What this release supports**：当前版本可用能力与限制。
5. **Get started**：上手指南、示例项目、AI / MCP 配置。
6. **For developers**：公开 JSON 规范和自定义生成器教程，产物就绪后再加。
7. **Release notes / Support / Terms and privacy**：版本记录、支持和条款。

现有宣传方向为 AI 编辑、精确评审、操作过程展示、JSON 与自定义生成。可以据此组织案例，但完整能力必须由对应公开版本的实际结果支撑；不要直接复制内部目标清单。

## 第二批：示例、规范和素材

| 内容 | 具体交付 |

| 一个可编辑示例项目 | 与演示对应的 `.yt` 作者文件、必要资源、打开步骤、预期结果和资源授权；先用自制内容 |

| 演示与截图 | 真实编辑器截图、评审前后对照、AI 修改结果和生成结果，注明对应版本 |

公开 JSON 是云图定义的交换规范，不宣称为行业标准；说明它与 `.yt` 作者文件的区别。生成器先证明一个具体输出可以重复生成，不承诺所有框架或完整业务系统。

条款、隐私政策可链接真实官网，也可使用本仓库内独立文档；地址和内容就绪后决定。`CHANGELOG.md` 负责用户可读的历史摘要，具体发行说明维护在对应 Release，不用内部提交日志代替。

## 备用安装包启用后再补什么

用户已明确：发布版本的最终产物必须先放在本项目 `releases/<产品版本>/<平台-架构>/`，按 `AGENTS.md` 的本地归档规则保存并核对。该目录属于本地发布交付位置，与是否启用 GitHub 分发无关；产物仍计入工作区共享 100 GB 额度、80 GB 预警。

若后续明确启用 GitHub 分发，再从本地归档准备安装包或便携包、版本说明、系统要求、SHA-256 校验清单、安装与升级说明、对应许可。二进制作为 Releases 附件管理，不放进 Git 历史。GitHub 自动生成的 Source code 压缩包只包含本资料仓库，不能作为编辑器安装包。

发布标签与产品版本对应，并记录实际编辑器源码提交、构建标识、包版本和附件摘要，避免资料仓库的 tag 被误当作编辑器源码版本。beta 标为预发布，公开入口指向实际对应的版本，不能提前把开发构建标成稳定发行。

不在本仓库自行添加 `latest.json` 并宣称实现自动更新。当前编辑器帮助页仍说明更新源未配置；商店更新与备用侧载包的更新机制需分别验证。SHA-256 校验也不等于受信更新或安装签名。

GitHub 对 Release 附件和自动生成的源码归档的说明见 [官方 Releases 文档](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。

- 最终使用条款、隐私政策、示例与生成器授权。
- 可公开截图、视频、示例项目及对应版本。

内部方案确定的国内免费、海外免费／Pro 以及各自容量与地域安排，在实现和发行确认前作为准备依据，不直接写成已经上线的价格或可购买功能。

## 推荐执行顺序

1. 先完成英文 README 草稿、英文快速上手、安装说明和 FAQ；缺失事实明确标注，暂不承诺上线。中文翻译不作为前置。
2. 用同一个真实项目补齐截图、演示、可编辑示例，再写 AI / MCP 指南和生成器教程。
3. 核对对应版本的规范、授权、隐私、支持渠道与商店链接，再定稿公开页面。
4. 发布时将最终产物归档到本项目。只有用户明确要求“推送到远程”时才执行相应 Git 推送；远程 Release、附件上传或商店提交按各自明确指令执行。本地准备与归档不构成远程发布授权。

源码、生产后台配置、数据库、凭据、用户项目、内部验收日志、无授权素材和构建缓存不属于本仓库内容。
