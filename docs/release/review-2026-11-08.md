# release/1.0.0-beta 整体 review

范围：Skill、MCP 交付、发布使用说明、版本一致性和准备检查。本轮只修改本地发布分支；不合并、不推送，不构建或修改正在验收的编辑器，也不发布。

## 结论

本轮发现并修复五类问题。当前资料可继续整体审阅；这不等于最终发行验收完成。用户固定目标、分支、版本说明模板及当前编辑器发行配置一致：`1.0.0-beta / beta / 1.0.0.0`。`main` 仍保持 `105698a`。

MCP 来源清单的 `observedEditorVersion: 1.0.0-beta.3` 和准备清单的历史观察是旧快照的真实来源；没有改写成新版本已验收。桥接 `serverInfo.version: 0.1.0` 是组件标识，不是本次编辑器发行号。最终安装包尚未交接，不能据此确认实际包内版本。

## 发现及修复

1. **P1 — Skill 要求了当前 MCP 无法调用的操作。** 原文要求原生校验、纯作品渲染和标准 JSON 导出，但这些方法不在当前桥接允许表中；编辑器 `ai.execute` 也没有开放对应写通道。改为 MCP Schema 与编辑器 capabilities 的交集，加入明确覆盖表和 GUI 操作边界。不用 `codegen.export` 代替标准导出，不通过直接 socket、shell 或改作者文件绕过桥接。保留 MCP 原始字节和既有保护。
2. **P2 — 重启后的连接恢复说明不完整。** 桥接只在启动时加载 discovery；UUID 启动示例每次产生新路径。补全正常关闭、停止旧 MCP、创建新 discovery、更新该服务 `--info`、重启桥接及重新读取身份的流程。区分进程重启导致的旧凭据与同进程文档切换的 session 变化。
3. **P2 — 版本目标可以被资料中的同步改号绕过。** 新增代码侧固定目标核对；同时将 `releaseTarget` 和分支改回 Beta.3 也会拒绝。最终身份和源码配置仍分别核对，历史来源不参与替代发行目标。
4. **P2 — 空清单可能跳过必要文件／事实检查。** 连接器来源清单必须包含两个运行文件和原协议测试；Store 事实字段不能通过删掉键或空对象逃过检查。缺失 helper、字段和空市场列表均有负例；删除或更换分发路线也不能关闭此次 MSIX 包检查。
5. **P2 — 归档前缀检查可被父目录路径绕过，普通说明文件也可能替代包。** 改为规范相对路径、解析后确实位于固定版本目录、文件长度和 SHA-256 检查，拒绝 Windows 分隔符绕行、父目录和重复大小写路径。所选 MSIX 路线必须记录对应提交包，不能只放 notes 或 EXE。这里只验证路径和字节，不取代原生安装／签名／Store 认证。

同时修正发布使用说明：标明此次具体版本、区分应用身份与桥接组件版本，并消除“禁止修改版本真源”与上轮用户明确要求已同步版本的矛盾。

## 本轮证据

- `python -B -m unittest discover -s scripts -p 'test_*.py'`：15 项通过，覆盖 8 项发行条件、5 项文件／事实边界和 2 项 MCP 交付检查。
- `python -B integrations/mcp/test-editor-mcp.py`：44 项原协议回归通过。原桥接、helper 和原测试文件的字节及来源摘要保持不变。
- 新 stdio 交付测试在独立 Python 子进程中完成 initialize → initialized → tools/list → editor_read；只访问测试创建的 loopback API stub，未接触任何真实编辑器或客户端。凭据是测试常量，不是用户 discovery 数据。
- 资料检查及 `--editor-identity` 比对通过；Codex TOML 示例可解析，本地文档引用有效。客户端设置方式按 [OpenAI MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) 和 [Skill 文档](https://learn.chatgpt.com/docs/build-skills) 核对。
- `skill-creator` 的 `quick_validate.py` 通过；使用临时 PyYAML 环境，没有修改全局客户端配置。
- 严格可发布检查仍因十一项待办、缺最终身份／产物和未批准商店事实返回 2，符合当前禁止发布的状态。
- 提交前核对 Git diff、UTF-8 without BOM、现有 LF／CRLF 及连接器原始字节；测试临时目录正常清理，未产生实际发行产物。

## 仍需最终交接

当前 MCP 只交付明确子集，不能称为全自动校验／渲染／标准导出。最终安装版的实际连接、原生读改保存与撤销、真实客户端／模型、重启重连、MSIX 安装升级、素材和许可尚需对应验收。域名审核与用户整体审阅仍保持等待。以上条件没有被单元测试、校验脚本或文档修改自动清除。
